> "这是我自己在腾讯云轻量服务器（2核2G，OpenCloudOS）上搭的实验环境，

> ⚠️ **不要说成是公司生产环境**。面试官一追问"你们公司业务量多少、几台机器、谁给你权限"，
> 立刻露馅。说成个人实验环境反而加分——说明你有自驱力。

### Q0-2：简历写"2 台 CentOS 节点"，你只有一台机器，怎么解释？
> "机器只有一台，我用 Docker 的网络命名空间隔离出两个独立节点，
> 每个节点有独立 IP、独立 hostname、独立的 Nginx+MySQL 实例，前面挂 Nginx 做负载均衡。
> 能覆盖集群运维里绝大部分排查场景：网络不通、端口冲突、主从延迟、数据卷权限。
> 但内核参数、磁盘 IO 这些是宿主机级别的，两个节点共享，
> 这点我知道，是这种模拟方式的边界。"

### Q0-3：你怎么证明这些是你做的？
> 准备这三样，面试时直接展示：
> 1. **GitHub 仓库**：把 `ops-portfolio` 整个目录传上去（配置、脚本、复盘文档都在）
> 2. **终端录屏/截图**：`docker ps`、`SHOW REPLICA STATUS\G`、`bench.sh` 的输出

## 一、Linux 系统

| 追问 | 答法要点 |
|---|---|
| 你配了哪些内核参数？为什么？ | somaxconn（accept 队列默认只有 128）、tcp_tw_reuse（TIME_WAIT 堆积）、file-max（fd 不够报 too many open files）、swappiness（2G 内存要留 swap 兜底）、ip_forward（Docker 跨网络转发必需） |
| 服务器卡了，你怎么排查？ | ① `top` 看 load 和 CPU；② `free` 看内存和 swap；③ `iostat -x 1` 看磁盘 %util、await；④ `ss -s` 看连接数；⑤ `dmesg \| tail` 看有没有 OOM kill。**顺序：CPU → 内存 → 磁盘 IO → 网络** |
| 端口被占用怎么查？ | `ss -tlnp \| grep :80` → 拿 PID → `ps -fp PID`。注意 Docker 场景还要 `docker ps -a` 看残留容器 |
| 磁盘满了但 du 找不到大文件？ | ★ `lsof \| grep deleted` —— 文件被删除但进程仍持有 fd，空间不会释放。解决：重启进程或用 `: > /proc/PID/fd/N` 在线清空 |
| Linux 启动流程？ | BIOS/UEFI → GRUB → kernel → systemd（或 init）→ target → 服务。CentOS 7+ 是 systemd，`systemctl` 管理 |
| 怎么看系统日志？ | systemd 系统用 `journalctl -u 服务名 --since "1 hour ago"`；传统日志在 `/var/log/messages`、`/var/log/secure`；内核用 `dmesg` |

## 二、网络

| 追问 | 答法要点 |
|---|---|
| 你简历写了抓包，抓过什么？ | "排查过 LB 到节点 502 的问题，在宿主机 `tcpdump -i any -nn -A port 80` 抓包，确认请求到达了 LB 但后端返回了 Connection refused，从而定位到是 php-fpm 没监听 0.0.0.0" |
| tcpdump 常用参数？ | `tcpdump -i eth0 -nn -s0 -w /tmp/cap.pcap host 1.2.3.4 and port 80`；`-nn` 不解析域名、`-s0` 抓完整包、`-w` 存盘用 Wireshark 分析 |
| TCP 三次握手，为什么不是两次？ | 两次无法确认客户端的接收能力；且会导致历史重复连接请求被误建立（三次握手可以用序列号判断是否过期） |
| TIME_WAIT 太多怎么办？ | ① 复用长连接；② `tcp_tw_reuse=1`；③ `tcp_tw_recycle` **别开**（NAT 环境会丢包，Linux 4.12 已移除）；④ 让服务端主动关闭的一方优化（HTTP Keep-Alive） |
| 502 和 504 的区别？ | 502 Bad Gateway：后端根本连不上（服务没起、端口错、进程崩了）。504 Gateway Timeout：连上了但后端处理超时。排查方向完全不同 |
| curl 常用排错参数？ | `-v` 看详细过程、`-I` 只要响应头、`-w '%{http_code} %{time_total}'` 看状态码和耗时、`-m 5` 设超时 |

## 三、Docker

| 追问 | 答法要点 |
|---|---|
| 镜像和容器的区别？ | 镜像是只读的模板（分层），容器是镜像的运行实例，在上面加了一层可写层 |
| 镜像分层有什么好处？ | 层可以复用和缓存。多个镜像共享基础层，拉取快、占空间小。我的 Dockerfile 里把 `apk del .build-deps` 和编译放在**同一层**，否则删掉的编译依赖还留在下层，镜像白变大 |
| 多阶段构建是什么？ | 一个 Dockerfile 里多个 FROM，编译阶段用大镜像（含编译器），运行阶段只拷二进制。Go 项目最典型：编译镜像 800MB，运行镜像 20MB。**说"了解"就够了，别吹用过** |
| CMD 和 ENTRYPOINT 区别？ | CMD 可被 `docker run` 后面的命令覆盖；ENTRYPOINT 不会被覆盖，后面的参数当它的参数 |
| volume 和 bind mount 怎么选？ | 数据库用 named volume（Docker 管权限，避开 SELinux/属主问题）；配置和代码用 bind mount（改了立即生效，可进版本管理）；配置再加 `:ro` 只读 |
| 挂载后面那个 `:z` 是啥？ | SELinux 标签。`:z` 多个容器共享，`:Z` 独占。不开 SELinux 的机器上没差别，开了之后不加就会 Permission denied |
| 容器怎么拿到宿主机 IP？ | `host.docker.internal`（需要加 `--add-host`）或用 `docker0` 网关地址；**生产更推荐用服务名而不是 IP** |
| docker logs 日志太大怎么办？ | 我在 daemon.json 里配了 `log-opts: max-size=20m, max-file=3` 做轮转，不然日志能把磁盘吃满（这是我踩过的坑之一） |
| 怎么清理磁盘？ | `docker system df` 看占用，`docker system prune -a --volumes` 清理（⚠ 会删未使用的 volume，小心） |

## 四、MySQL

| 追问 | 答法要点 |
|---|---|
| 主从复制原理？ | 主库写 binlog → 从库 IO 线程拉取写入 relay log → SQL 线程回放 relay log。三个线程，两阶段 |
| IO 线程和 SQL 线程分别挂了说明什么？ | IO 挂：网络/账号/主库问题（连不上）。SQL 挂：数据冲突或从库执行出错（比如 1062 主键冲突、1032 找不到行）。**看 Last_IO_Error / Last_SQL_Error 区分** |
| Seconds_Behind_Master 准吗？ | 是估算值，基于 binlog 时间戳差值。大事务时会跳变；IO 线程断了显示为 NULL；**不能作为唯一依据**，要结合 GTID 差值判断 |
| GTID 比传统复制好在哪？ | 故障切换时不用人工算 binlog 文件名+position，`MASTER_AUTO_POSITION=1` 自动找位点。代价是事务有限制（不能混用引擎等） |
| 主从延迟怎么优化？ | ① 并行复制 `slave_parallel_workers`（我配了 2 个，LOGICAL_CLOCK）；② 拆大事务；③ 主从索引保持一致；④ `binlog_row_image=MINIMAL` |
| 备份为什么用 --single-transaction？ | InnoDB + RR 隔离级别下拿一致性快照，不锁表。有 MyISAM 表则无效 |
| 索引越多越好吗？ | 不是。每个索引一棵 B+ 树，写操作要维护所有索引；还占 buffer pool；索引多了优化器可能选错。我控制在单表 5~6 个，优先复合索引 |
| 什么叫回表？ | 二级索引叶子节点存的是主键值，拿到主键后还要回主键树查整行。用覆盖索引（查询列都在索引里）可以避免，Extra 会显示 Using index |
| 最左前缀原则？ | 复合索引 (a,b,c) 相当于建了 (a)、(a,b)、(a,b,c) 三个索引。所以有了 (a,b,c) 就不用再建 (a) |
| 为什么范围条件后的列用不上索引？ | B+ 树在范围内无法保证后续列有序 |
| 索引失效的常见场景？ | 隐式类型转换（字符串字段传数字）、对列用函数、前导模糊查询 `%xx`、`OR` 连接不同列、违反最左前缀 |
| MySQL 慢你怎么排查？ | ① `SHOW PROCESSLIST` 看当前在跑什么；② 看慢日志；③ EXPLAIN 分析；④ 看锁等待 `SHOW ENGINE INNODB STATUS`；⑤ 看系统资源（IO 打满会导致全库慢） |

## 五、Shell 与自动化

| 追问 | 答法要点 |
|---|---|
| 备份脚本怎么保证不会悄悄失败？ | ① `set -uo pipefail`；② 每步判断返回值；③ 备份完 `gzip -t` 校验文件完整性；④ 失败调告警；⑤ **每周做恢复演练**验证 |
| crontab 为什么经常不执行？ | ★ 三大原因：① **环境变量**（cron 的 PATH 很短，脚本里要用绝对路径或 source /etc/profile）；② 脚本没有执行权限或 CRLF 换行；③ 没有重定向输出，报错看不到。我的做法是在 crontab 里都加 `>> /path/to.log 2>&1` |
| 你怎么知道定时任务跑了没有？ | 看 `/var/log/cron`，看脚本自己的日志文件，以及备份文件的 mtime |
| awk / sed 常用吗？ | 准备两个真实例子：`awk '{print $1}' access.log \| sort \| uniq -c \| sort -rn \| head` 统计 IP 访问 Top10；`sed -i 's/old/new/g'` 批量替换配置 |

## 六、场景题（面试官最爱问的开放题）

**「网站打开很慢，你怎么排查？」**
> 分层定位，从外到内：
> 1. 客户端：`curl -w '%{time_connect} %{time_starttransfer} %{time_total}'` 拆开各阶段耗时
> 2. DNS/网络：ping 看延迟、mtr 看链路哪一跳丢包
> 3. Nginx：看 access_log 里的 `$request_time` 和 `$upstream_response_time`
>    —— ★ 这两个值一对比，就能判断慢在 Nginx 还是慢在后端
> 4. 应用层：PHP 慢日志（`request_slowlog_timeout`）、数据库慢查询
> 5. 系统层：CPU、内存、磁盘 IO、连接数

**「数据库 CPU 100% 怎么办？」**
> ① `SHOW PROCESSLIST` 找出运行时间长的 SQL；
> ② 看慢日志确认高频慢查询；
> ③ EXPLAIN 看是否走索引；
> ④ 紧急处理：kill 掉问题会话；
> ⑤ 根治：加索引 / 改 SQL / 加缓存。
> 注意区分是**慢查询导致 CPU 高**，还是**并发太高**——处理方式完全不同。

**「线上要改一个索引，你会怎么做？」**
> ① 先在测试环境验证（我这套环境就是干这个的）；
> ② 确认表大小和当前 QPS，评估影响；
> ③ MySQL 8.0 支持 `ALGORITHM=INPLACE, LOCK=NONE` 的在线 DDL，但大表仍有风险；
> ④ 选业务低峰期执行；
> ⑤ 提前备份，准备好回滚语句（DROP INDEX）；
> ⑥ 执行后观察慢查询和监控。
> 如果版本不支持在线 DDL，用 pt-online-schema-change 或 gh-ost。

**「如果发现有人误删了数据库？」**
> ① 立即止损，必要时先停写；
> ② 确认最新的全量备份 + binlog 是否完整；
> ③ 恢复到临时实例（不要直接覆盖生产）；
> ④ 用 mysqlbinlog 做时间点恢复（PITR），重放到误操作前一刻；
> ⑤ 核对数据后回灌生产；
> ⑥ 复盘：权限收敛、高危操作二次确认、备份策略检查。
> ★ 关键：**binlog 必须是 ROW 格式且保留足够长**，否则 PITR 做不了。
