## 一、Linux 系统排查（占 Linux 面试约 40%，先背这块）

### Q1 ★ 服务器突然变慢 / 卡住了，你怎么排查？

**答题框架——先给结论，再分层展开**（面试官听的是你有没有章法，不是你能背多少命令）：

> 「我会按 **CPU → 内存 → 磁盘 IO → 网络 → 内核日志** 的顺序分五层定位：
> ① `top` 看 load average 和 CPU 各核占用，按 `1` 展开每核，`P` 按 CPU 排；
> ② `free -h` 看内存和 swap，重点看 `available` 而不是 `used`；
> ③ `iostat -x 1` 看磁盘，重点看 `%util` 和 `await`；
> ④ `ss -s` 看连接总数和 TIME_WAIT 堆积；
> ⑤ `dmesg | tail` 看有没有 OOM Kill。」

**追问链（面试官会顺着往下挖）：**

| 追问 | 你要答出来的点 |
|---|---|
| load 很高但 CPU 使用率很低，怎么回事？ | ★ load 统计的是**运行队列 + 不可中断状态（D 状态）**进程数。IO 打满时大量进程卡在 D 状态，CPU 闲着但 load 飙高。`vmstat 1` 看 `b` 列确认 |
| 怎么确认是磁盘 IO 的问题？ | `iostat -x 1`：`%util` 接近 100% = 设备饱和，`await` 是平均响应毫秒。再看 `vmstat` 的 `b` 列 |
| 知道了磁盘 IO 高，怎么定位是哪个进程？ | `iotop -oP`（需安装）或 `pidstat -d 1`；没有的话用 `for p in /proc/[0-9]*; do ...` 看 `/proc/PID/io`（说出前两个即可，第三个是加分） |
| `free` 看到内存几乎用完了，是不是有问题？ | ★ 不是。`buff/cache` 是内核拿来当缓存的，**内存闲着也是闲着**。要看 `available`。这是区分「背过」和「真用过」的分水岭 |
| swap 被用了说明什么？ | 内存在往磁盘换页，性能会断崖式下降。看 `vmstat` 的 `si/so`，**非 0 就是内存不足**。2G 内存的机器要留 swap 兜底，但 `swappiness` 别设太高 |
| 找到了问题进程之后呢？ | 先看它是谁（`ps -fp PID`、看 cgroup 判断是不是容器），再看它在干什么（`lsof -p PID`、`strace -p PID`），**最后才决定是 kill 还是限流** |

**丢分点：** 上来就说「重启一下」——面试官直接判死刑。

### Q2 ★ 磁盘满了，你怎么处理？

> 「分三步：确认 → 定位 → 清理。
> ① `df -h` 确认哪个分区满；顺便 `df -i` 看是不是 **inode 耗尽**（小文件太多会空间还剩但写不进去，这是经典第二种情况）；
> ② 定位大文件：`du -h --max-depth=1 / | sort -rh | head`，或 `find / -type f -size +500M`；
> ③ 清理：日志优先用 `truncate` 而不是直接 `rm`，避免正在写的进程出问题；确认能删再删。」

**追问链：**

| 追问 | 答点 |
|---|---|
| ★ `df` 显示 100%，但 `du` 加起来对不上，找不到大文件？ | **「文件被删除了但进程还持有 fd，空间不会释放」**。用 `lsof \| grep deleted` 找出来，重启进程或 `: > /proc/PID/fd/N` 在线清空。★ 这题答出来基本能证明你真干过 |
| 为什么建议 truncate 而不是 rm 日志文件？ | 进程持有的是 inode，`rm` 只是删目录项，空间不释放且进程还在往已删的文件写；`truncate -s 0 file` 直接把文件清零，进程继续正常写 |
| 怎么防止再发生？ | ① logrotate 做日志轮转；② Docker 配 `log-opts: max-size=20m, max-file=3`（★ 你踩过这个坑，一定要说）；③ 监控磁盘使用率提前告警 |

### Q3 ★ 端口被占用怎么查？

> `ss -tlnp \| grep :80` → 拿到 PID → `ps -fp PID` 看是什么进程。
> 或者反过来 `lsof -i:80`。
> 如果是 Docker 环境，还要 `docker ps -a` 看有没有残留容器占着端口。

**追问链：** `ss` 和 `netstat` 有什么区别？（ss 直接读内核 `tcp_diag`，快得多，netstat 遍历 `/proc`，连接多时卡死）
`ss -tn state established \| wc -l` 能干什么？（看 ESTABLISHED 连接数，判断并发）
TIME_WAIT 特别多正常吗？（短连接主动关闭方会有，见网络部分 Q17）

---

### Q4 一个进程 CPU 跑到 100%，怎么定位是哪段代码/哪个线程？

> ① `top` 找 PID；② `top -Hp PID` 或 `ps -Lp PID` 看哪个线程吃 CPU；
> ③ 线程 ID 转 16 进制（`printf '%x\n' TID`）——Java 场景再对照 `jstack`；
> ④ 不是 Java 就看 `perf top -p PID` 或 `strace -p PID` 看卡在哪个系统调用。
>
> 运维岗**知道前两步就够**，第三步说出「转 16 进制对照堆栈」是加分项。

---

### Q5 服务起不来，你怎么排查？

> ① `systemctl status 服务名` 看状态和最近几行日志（**这一步能解决 70%**）；
> ② `journalctl -u 服务名 -n 50 --no-pager` 看完整报错；
> ③ 手动前台跑一次看输出（比如 `nginx -t` 先测配置）；
> ④ 查依赖：端口占用、配置目录权限、数据目录属主、依赖服务没起。

★ 加分：说一句「`nginx -t`、`sshd -T`、`php-fpm -t` 这类 `-t` 测配置的习惯，改配置前先验证」——说明你有生产意识。

## 二、命令与文本处理（常考，且能现场让你手写）

### Q6 现场写：找出 /var/log 下 7 天前修改、大于 100M 的 .log 文件并删除

```bash
find /var/log -type f -name "*.log" -mtime +7 -size +100M -delete
# 稳妥版（先看再删）：
find /var/log -type f -name "*.log" -mtime +7 -size +100M -exec ls -lh {} \;
```

★ 追问：`-mtime +7` 和 `-mtime -7` 有什么区别？（`+7` = 严格 7 天之前；`-7` = 7 天之内；`7` 正好是第 7 天）

### Q7 现场写：统计 Nginx 日志里访问量最高的 10 个 IP

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10
```
★ 追问：`sort -rn` 的 `-n` 为什么必须加？（不加按字符串排，"9" 会排在 "10" 后面）
`uniq -c` 为什么前面必须先 `sort`？（uniq 只去重**相邻**行）

### Q8 批量替换多个配置文件里的旧 IP

```bash
grep -rl "1.2.3.4" /etc/nginx/ | xargs sed -i.bak 's/1.2.3.4/5.6.7.8/g'
```
★ 追问：为什么加 `.bak`？（改配置前留备份，改错了能回滚——**说这句比答出命令更值钱**）

### Q9 软链接和硬链接的区别？（必考）

| | 软链接 `ln -s` | 硬链接 `ln` |
|---|---|---|
| inode | 新的 | 和源文件**同一个** |
| 跨分区 | 可以 | 不行 |
| 指向目录 | 可以 | 不行 |
| 源文件删除后 | ★ 链接失效（红闪） | 文件还在（引用计数 -1） |
| 典型用途 | 版本切换、配置软链 | 几乎不用 |

### Q10 `cp -a` 和 `cp -r` 区别？
`-a` = `-dR --preserve=all`，**保留权限、属主、时间戳且不跟随软链接**。备份场景必须用 `-a`，用 `-r` 备份出来的文件权限全变了，恢复回去一堆 644/755 问题。

### Q11 改了 `/etc/hosts` 不生效 / 文件明明存在却读不到？
常见：① DNS 缓存（nscd/systemd-resolved）；② 应用自己有连接池缓存了解析结果；③ 容器内改的是容器自己的 hosts，宿主机的没改。

## 三、权限（你简历写了「排查权限异常」，这里必被追）

### Q12 755 / 644 / 600 分别代表什么？
`r=4 w=2 x=1`。755 = 属主 rwx、组和其他 rx（可执行文件/目录）；644 = 属主 rw、其他只读（普通文件）；600 = 只有属主可读写（★ **私钥必须是 600，否则 SSH 直接拒绝使用**）。

### Q13 ★ 目录没有 x（执行）权限会怎样？
能 `ls` 出文件名，但**不能 cd 进去、不能访问里面任何文件**，报 `Permission denied`。
因为 x 对目录的含义是「能否穿越（traverse）」。这是最经典的权限陷阱题。

### Q14 执行脚本报 `Permission denied`，除了没 chmod +x 还有什么原因？

> ★ 这题答得全不全，直接区分「背过」和「踩过坑」：
> 1. 脚本本身没执行权限（`chmod +x`）
> 2. **shebang 路径错**：`#!/bin/bash` 写成了 `#!/bin/sh` 或 Windows 编辑后变成 `#!/bin/bash\r` —— CRLF 会让解释器名带上回车，报 `bad interpreter`
> 3. ★ **挂载选项带 `noexec`**：`mount \| grep noexec`，数据盘常这样
> 4. ★ **SELinux**：文件上下文不对，`ls -Z` 看，`restorecon -Rv` 修（你在 OpenCloudOS 上做过，一定要讲）
> 5. 文件系统被只读挂载（`mount \| grep ro`，磁盘出错后内核会自动 remount ro）
> 6. 父目录没 x 权限

### Q15 `chown -R nginx:nginx /var/www` —— 顺序写反了会怎样？
写成 `nginx.nginx` 也行（点号分隔），但写成 `chown /var/www nginx:nginx` 顺序反了会把目录当用户名报 `invalid user`。另外 `usermod -aG` 的 `-a` 忘了加会**清空用户原有附加组**（经典事故）。

## 四、网络（简历写了抓包，这块会被连挖三层）

### Q16 ★ 三次握手 / 四次挥手

**三次握手**：客户端 SYN → 服务端 SYN+ACK → 客户端 ACK。
★ 追问「为什么不是两次」：两次只能确认客户端的发送能力和服务端的接收能力，**确认不了客户端的接收能力**；且历史重复的 SYN 会被误建立连接，三次握手可以用序列号判断合法性。

**四次挥手**：主动方 FIN → 被动方 ACK（半关闭，被动方还能发数据）→ 被动方 FIN → 主动方 ACK。
★ 追问「为什么握手三次、挥手四次」：因为服务端收到 SYN 时可以把 SYN 和 ACK **合并**发送；而收到 FIN 时可能还有数据没发完，ACK 和自己的 FIN 得分开发。

### Q17 ★ TIME_WAIT 大量出现，是什么原因、怎么办？

> 「TIME_WAIT 出现在**主动关闭连接的一方**。大量出现通常是短连接 + 高并发，服务端（或客户端）频繁主动断开。
> 处理：① 优先用长连接 / 连接池（HTTP Keep-Alive、数据库连接池）；
> ② `net.ipv4.tcp_tw_reuse = 1` 允许复用；
> ③ ★ `tcp_tw_recycle` **绝对不要开**——NAT 环境下会导致大量连接被拒，Linux 4.12 已移除这个参数；
> ④ 负载高时可以把短连接改成由客户端主动关闭，让 TIME_WAIT 散在客户端。」

★ 说出第 ③ 点（别开 tw_recycle 及原因）是明显的加分项，大部分候选人只会背「tw_reuse 和 tw_recycle 都开」。

### Q18 ★ 502 和 504 的区别？

| | 含义 | 排查方向 |
|---|---|---|
| **502 Bad Gateway** | 后端**连不上**（服务没起 / 端口错 / 进程崩 / 连接池满） | `ss -tlnp` 看后端端口在不在、`curl 127.0.0.1:端口`、看后端错误日志 |
| **504 Gateway Timeout** | 连上了但**后端处理超时** | 后端慢，查慢查询、查应用耗时、调 `proxy_read_timeout` |

★ 一句话记忆：**502 是够不着，504 是够着了但太慢**。方向完全不同。

### Q19 tcpdump 你抓过什么？常用参数？

> 「排查 LB 到后端 502 时，在宿主机 `tcpdump -i any -nn -A port 80` 抓包，
> 确认请求到达了 LB 但后端回了 `Connection refused`，定位到是 php-fpm 只监听了 127.0.0.1 没监听 0.0.0.0。」

常用参数：`-i` 网卡、`-nn` 不做域名/端口名解析（快且输出直观）、`-s0` 抓完整包不截断、`-w file.pcap` 存盘拿 Wireshark 分析、`-A` 以 ASCII 打印内容、`host x.x.x.x and port 80` 过滤。

★ 追问：`-nn` 为什么重要？（不解析 DNS，避免抓包时产生额外 DNS 查询污染结果，也避免卡顿）

### Q20 怎么判断问题是出在网络还是应用？

> ① `curl -w '%{time_connect} %{time_starttransfer} %{time_total}'` 拆开各阶段：
>    `time_connect` 大 = 网络/TCP 层问题；`time_starttransfer - time_connect` 大 = 后端处理慢。
> ② `mtr` 看链路哪一跳丢包。
> ③ Nginx 里对比 `$request_time` 和 `$upstream_response_time`：两者接近 = 慢在后端；差值大 = 慢在 Nginx 自己（或客户端网络慢）。

### Q21 服务进程在，`telnet` 端口却不通，可能是什么原因？
① 监听在 `127.0.0.1` 而不是 `0.0.0.0`（★ 最常见，容器场景尤甚）；
② 防火墙 / 云厂商安全组没放行；
③ 中间有 LB 或代理；
④ 连接队列满了（`somaxconn` 太小）；
⑤ 你 telnet 的机器和目标不是同一台 / 走了 NAT。

## 五、系统与服务管理

### Q22 Linux 启动流程？
BIOS/UEFI → MBR/GPT 上的 **GRUB2** → 加载 kernel 和 initramfs → 第一个用户态进程 **systemd**（PID 1）→ 按 default.target 拉起服务 → 登录终端。
CentOS 7+ / Ubuntu 16+ 都是 systemd。

### Q23 怎么让一个脚本开机自启？三种方式
① 写 systemd unit（**生产推荐**，能管重启策略和日志）；
② `/etc/rc.local`（要 `chmod +x`，简单但不被 systemd 纳管）；
③ `crontab` 里 `@reboot /path/script.sh`。

### Q24 ★ `reload` 和 `restart` 的区别？
`reload` 让进程**重新加载配置，不断开已有连接**（Nginx 会起新 worker、老 worker 处理完现有请求再退出）；`restart` 是先 stop 再 start，连接全断。
★ **生产环境优先 reload**，改监听地址/端口这类必须 restart 才行。

### Q25 ★ 定时任务没执行，你怎么排查？（你简历写了 crontab，必问）

> 三个高频原因：
> ① **环境变量**：cron 的 PATH 极短（通常只有 `/usr/bin:/bin`），手动跑成功挂 cron 就失败。→ 脚本里用绝对路径，或在脚本开头 `source /etc/profile`；
> ② 脚本**没有执行权限**，或是 Windows 编辑的 CRLF 换行（★ 你实际踩过）；
> ③ 没有重定向输出，报错看不见 → crontab 里都加 `>> /var/log/xxx.log 2>&1`；
> ④ 再加一条：`cron` 服务本身没起（`systemctl status crond`）、`%` 在 crontab 里要转义成 `\%`。
>
> 查证：`cat /var/log/cron` 看有没有触发记录。

### Q26 怎么看昨天的 CPU / 内存历史？（现在正常，昨晚高峰有问题）
`sar -r` 看内存历史、`sar -u` 看 CPU、`sar -n DEV` 看网卡流量（sysstat 包会每 10 分钟采样）。没有装 sysstat 就看监控系统的历史曲线。

### Q27 你配过哪些内核参数，为什么？（你简历写了「内核参数」，必问）
> 「`net.core.somaxconn`（accept 队列默认只有 128，并发上来会丢连接）、
> `net.ipv4.tcp_tw_reuse=1`（TIME_WAIT 复用）、
> `fs.file-max`（fd 不够会报 too many open files）、
> `vm.swappiness`（2G 内存留 swap 兜底，但别太激进）、
> `net.ipv4.ip_forward=1`（Docker 跨网络转发必需）」
> ★ 每条都要能说出「**不配会怎样**」，只报参数名等于没答。

## 六、Shell（简历写了「编写 Shell 脚本」，通常会让你现场写）

### Q28 现场写：备份 MySQL 并只保留最近 7 天

```bash
#!/bin/bash
set -euo pipefail                      # ★ 说出这三位的含义是加分：e 出错即退 / u 未定义变量报错 / o pipefail 管道任一段失败即失败

BACKUP_DIR="/backup/mysql"
KEEP_DAYS=7
DATE=$(date +%F)
LOG="/var/log/mysql_backup.log"

mkdir -p "$BACKUP_DIR"
mysqldump -uroot -p"$MYSQL_PWD" --single-transaction --routines appdb \
  | gzip > "$BACKUP_DIR/appdb_$DATE.sql.gz"

gzip -t "$BACKUP_DIR/appdb_$DATE.sql.gz"   # ★ 校验完整性，备份不做校验等于没备份
echo "$(date '+%F %T') backup ok: $DATE" >> "$LOG"

find "$BACKUP_DIR" -name "*.sql.gz" -mtime +$KEEP_DAYS -delete
```

★ 加分点（一定要主动说出来）：
- `set -euo pipefail`
- `gzip -t` 校验
- 密码不写进脚本和命令行（用 `~/.my.cnf` 或环境变量），否则进 `history` 和 `ps` 输出
- **备份完要做恢复演练**——这句话说出来面试官印象最深

### Q29 怎么防止脚本被重复执行（上一个还没跑完，cron 又起了一个）？
① `flock -n /tmp/backup.lock -c '/opt/backup.sh'`（★ 推荐，最干净）；
② 脚本开头写 pid 文件 + 判断进程是否存在；
③ 用 `pgrep -f script.sh` 自查。

### Q30 `$*` `$@` `$#` `$?` `$$` 分别是什么？
`$#` 参数个数、`$?` 上一条命令退出码、`$$` 当前脚本 PID、`$0` 脚本名；`$*` 把所有参数当一个字符串，`$@` 保持每个参数独立——**循环时要用 `"$@"`**，用 `$*` 会被空格拆乱。

## 七、场景开放题（每题给答题框架，按框架答就不会乱）

> 通用心法：**先止损 → 再定位 → 再根治 → 最后复盘**。
> 面试官看的是顺序，不是你能不能一步到位。

### S1 ★ 用户反馈网站打开很慢，你怎么排查？
分层从外到内：
1. 客户端侧：`curl -w` 拆开 DNS 时间 / 连接时间 / 首字节时间 / 总时间
2. 网络：`ping` 看延迟、`mtr` 看哪一跳丢包
3. Nginx：对比 `$request_time` 与 `$upstream_response_time`，判断慢在 Nginx 还是后端
4. 应用：PHP 慢日志、数据库慢查询
5. 系统：CPU / 内存 / 磁盘 IO / 连接数

### S2 ★ 数据库 CPU 100% 怎么办？
① `SHOW PROCESSLIST` 找运行时间长的会话；② 慢日志确认高频慢 SQL；③ `EXPLAIN` 看走没走索引；
④ 紧急：`KILL` 问题会话；⑤ 根治：加索引 / 改 SQL / 加缓存。
★ 关键区分：**是慢查询拖高的，还是并发太高**——前者改 SQL，后者限流/扩容，处理方向完全不同。

### S3 ★ 网站突然 502 了？
① 确认影响面（全部还是部分接口）；② 查后端在不在：`ss -tlnp` + `curl 127.0.0.1:端口`；
③ 看 Nginx error_log 的 `connect() failed` / `Connection refused`；④ 看后端为什么没了（OOM？crash？磁盘满？）；
⑤ 恢复后查根因（`dmesg | grep -i oom`）。

### S4 ★ 线上要加一个索引，你会怎么做？
① 测试环境先验证；② 评估表大小和当前 QPS；③ MySQL 8.0 用 `ALGORITHM=INPLACE, LOCK=NONE` 在线 DDL，但大表仍有风险；
④ 选业务低峰期；⑤ **提前备份 + 准备好回滚语句 `DROP INDEX`**；⑥ 执行后盯慢查询和监控。
★ 版本不支持就用 `pt-online-schema-change` 或 `gh-ost`（说出名字即可）。

### S5 ★ 有人误删了数据库，怎么救？
① 立即止损，必要时先停写；② 确认最新全量备份 + binlog 是否完整；
③ **恢复到临时实例，不要直接覆盖生产**；④ `mysqlbinlog` 做时间点恢复（PITR），重放到误操作前一刻；
⑤ 核对数据后回灌；⑥ 复盘：权限收敛、高危操作二次确认、备份策略检查。
★ 关键前提：**binlog 必须是 ROW 格式且保留足够长**，否则 PITR 做不了。

### S6 ★ 备份脚本一直在跑，但其实是失败的呢？（怎么保证备份可用）
① `set -uo pipefail` + 每步判返回值；② 备份完 `gzip -t` 校验；③ 校验失败立刻告警；
④ ★ **每周做一次恢复演练**——不演练的备份等于没有备份；
⑤ 看备份文件 mtime 和大小是否符合预期（突然变小说明 dump 出问题了）。

### S7 给你一台新机器上线，你会做哪些初始化？
分区/挂载 → 主机名、时区、NTP 同步 → 建普通用户 + sudo、SSH 密钥登录 + 禁密码 + 改端口 → 防火墙/安全组最小化放行 →
内核参数调优 → 装监控 agent → 配日志轮转 → 配备份任务 → 写初始化文档。
★ 按顺序说，并在「安全」那几步上停一下强调。

### S8 你怎么判断服务器是不是被入侵了？（加分题，应届生基本答不出）
① `last` / `lastb` 看异常登录 IP 和时间；② `w` 看当前在线用户；
③ `cat /var/log/secure` 看大量失败登录（暴力破解）；④ crontab -l 和各用户 cron 里有没有可疑任务；
⑤ `ss -tlnp` 看有没有陌生监听端口；⑥ `ps -ef` 看异常进程、CPU 长期 100% 的挖矿进程；
⑦ 检查 `/etc/passwd` 有没有新增 UID 0 的账号、`authorized_keys` 有没有被加公钥。

## 十、练习方法 & 评分标准

### 三遍练习法
1. **第一遍（自测）**：遮住答案，每题出声答一遍，卡住的打叉
2. **第二遍（对答案）**：只练打叉的题，并把命令**回服务器真敲一遍**（敲过才记得住）
3. **第三遍（模拟）**：找人（或让我）按追问链连挖三层，练「被追着问还不慌」

### 一题答到什么程度算过关

| 层级 | 表现 | 评价 |
|---|---|---|
| L1 | 能说出用什么命令 | 及格 |
| L2 | 能说出**为什么用这个命令**、参数什么意思 | 良好 |
| L3 | ★ 能说「我在自己机器上跑过，当时看到 XXX，后来发现是 XXX」 | **优秀，基本稳了** |

> **面试官真正筛的是 L3。** 所以每道题都尽量挂一句你的真实经历——
> 哪怕只是「我在 2C2G 那台机器上跑 `iostat` 时看到 `%util` 打满，查出来是备份脚本和业务抢 IO」这种小细节。

### 最后一道自检

| 问题 | 能答吗 |
|---|:--:|
| 被问「你只有一台机器，两台节点怎么回事」时能不慌地交底吗 | ☐ |
| 「服务器卡了」能不看笔记说出五层排查顺序吗 | ☐ |
| 磁盘满但 du 查不到大文件，知道是 deleted 句柄吗 | ☐ |
| Permission denied 能说出 4 种以上原因吗 | ☐ |
| TIME_WAIT 会说「tw_recycle 别开」吗 | ☐ |
| 502 / 504 能一句话说清区别吗 | ☐ |
| 备份脚本能默写出 `set -euo pipefail` + `gzip -t` 吗 | ☐ |
| 能说出「备份要做恢复演练」和「binlog 要 ROW 格式」吗 | ☐ |
| 简历上那 5 个坑改掉了吗 | ☐ |

**简历先改，再背题，最后回服务器敲一遍。**
