## 一、目录与文件（1–10）

| # | 命令 | 作用 | 什么时候用 |
|---|---|---|---|
| 1 | `pwd` | 显示当前所在路径 | 用户说「文件找不到了」，先确认自己在哪 |
| 2 | `ls -lh` | 列表 + 人类可读大小 | 看文件多大、属主是谁、什么时候改的 |
| 3 | `ls -la` | 含隐藏文件（`.` 开头） | 找不到 `.bashrc`、`.env`、`.git` |
| 4 | `cd -` | 回到上一个目录 | 在两个目录间来回跳，不用记路径 |
| 5 | `mkdir -p /data/app/logs` | 递归建目录 | `-p` 目录已存在也不报错，脚本里必加 |
| 6 | `cp -a src dst` | 复制并保留权限/时间/属主 | **备份配置**用 `-a`，用 `cp` 会丢权限 |
| 7 | `mv a b` | 移动 / 同目录内是重命名 | 改文件名、挪目录 |
| 8 | `rm -rf dir` | 递归强删 | 只在确认路径后敲；线上先 `ls` 看清再删 |
| 9 | `touch f` | 建空文件 / 更新时间戳 | 触发日志轮转、测目录写权限 |
| 10 | `find /var/log -name "*.log" -mtime +7` | 按名字/时间/大小找文件 | `+7` 是 7 天**前**，`-7` 是 7 天内（爱考） |

**一句话**：日常操作就这 10 条，`pwd` → `ls -lh` → `cd` 是排查任何问题的起手式。

## 三、权限与用户（21–30）

| # | 命令 | 作用 | 什么时候用 |
|---|---|---|---|
| 21 | `ls -l f` ★ | 看 `-rw-r--r--` 权限位 | 报 `Permission denied` 第一步 |
| 22 | `chmod 644 f` | 属主读写、其他人只读 | **文件默认就用 644** |
| 23 | `chmod 755 d` | 属主全权、其他人读+执行 | **目录默认 755**，脚本也要 `+x` |
| 24 | `chmod +x s.sh` | 加执行权限 | 脚本报 `Permission denied` 或 `bad interpreter` |
| 25 | `chown -R www:www /var/www` ★ | 改属主属组 | 属主不对就 `chown`，**不要 `chmod 777`** |
| 26 | `chgrp` | 只改属组 | 多人协作目录 |
| 27 | `umask` | 默认权限掩码 | 新建文件权限不对时查它 |
| 28 | `whoami` / `id` | 当前用户 / UID、所属组 | 先确认「我是谁」，很多问题就是用户错了 |
| 29 | `sudo cmd` vs `su -` | 单条提权 / 切换登录 | `su -` 带 `-` 才会加载目标用户环境变量 |
| 30 | `useradd` / `usermod -aG docker u` | 建用户 / 加组 | 加组必须 `-a`，否则会覆盖原有组（坑） |

> **必答追问**：为什么不直接用 `chmod 777`？
> 777 = 所有人都能读、写、执行，普通账号能篡改程序；目录 777 意味着**谁都能删别人的文件**。属主错就 `chown`，是 SELinux 拦的就打标签，777 只会掩盖问题还留安全洞。

## 四、进程与服务（31–40）

| # | 命令 | 作用 | 什么时候用 |
|---|---|---|---|
| 31 | `ps aux \| grep nginx` ★ | 查进程是否存在 | 判断「服务到底起没起」 |
| 32 | `ps -ef \| grep java` | 同上，带 PPID | 看父子进程、谁拉起的 |
| 33 | `pgrep -l nginx` | 只出 PID + 名字 | 比 `ps\|grep` 干净，不会匹配到自己 |
| 34 | `top` ★ | 实时看 CPU/内存 | 进去按 `1` 看每核，按 `M` 按内存排序 |
| 35 | `top -Hp PID` | 看线程级 | Java 服务 CPU 高，找具体线程 |
| 36 | `kill -15 PID` ★★ | 发 SIGTERM，优雅退出 | **首选**，让程序自己收尾、存盘 |
| 37 | `kill -9 PID` | SIGKILL，强杀 | **最后手段**，进程没机会存盘、连接不断开 |
| 38 | `killall nginx` | 按名字杀全部 | 同一程序起了多个实例 |
| 39 | `nohup cmd &` | 后台跑且退出终端不挂断 | 临时长任务，输出记得重定向 |
| 40 | `systemctl status nginx` ★★ | 服务状态 + 最近日志 | 再配 `start/stop/restart/reload`、`enable` 开机自启 |

> **必答追问**：`restart` 和 `reload` 的区别？
> `reload` 只重新加载配置、**不断已有连接**（Nginx 改配置用这个）；`restart` 停掉再起，**连接会断**。
> `kill -9` 会留下什么？端口可能还在 TIME_WAIT、临时文件不清理、数据库可能损坏。

## 五、磁盘与内存（41–50）

| # | 命令 | 作用 | 什么时候用 |
|---|---|---|---|
| 41 | `df -h` ★★ | 各分区使用率 | 「磁盘满了」第一步，看哪个分区 100% |
| 42 | `df -i` ★ | inode 使用率 | **磁盘没满却写不进去**，八成是 inode 用尽（小文件太多） |
| 43 | `du -sh *` ★ | 当前目录下每项多大 | 只输出一行，比 `du -h` 清爽 |
| 44 | `du -sh /* \| sort -rh \| head` ★ | 找出最大的顶层目录 | 一层层下钻定位大目录 |
| 45 | `find / -type f -size +500M` | 找大于 500M 的文件 | 大文件清理、日志没轮转 |
| 46 | `lsof \| grep deleted` ★★★ | 已删除但仍被进程占用的文件 | **`df` 满了 `du` 却查不到**，就是这个（删了文件没重启服务） |
| 47 | `lsblk` | 块设备树 | 看有几块盘、挂在哪、有没有没挂的 |
| 48 | `mount` / `umount` | 挂载 / 卸载 | 挂新盘、挂 ISO |
| 49 | `free -h` ★ | 内存使用 | **看 `available` 不看 `free`**，Linux 会拿空闲内存做缓存 |
| 50 | `swapon --show` | swap 使用 | swap 用得很多 = 内存真的紧张 |

> **必答追问**：`df` 显示满了，`du` 加起来却差很多，为什么？
> ① **已删除但被进程占用的文件**（`lsof | grep deleted`，重启进程释放）；
> ② 被覆盖挂载的目录（挂载点下面还藏着文件）；
> ③ 文件系统保留块（ext4 默认给 root 留 5%）。

## 六、网络与端口（51–60）

| # | 命令 | 作用 | 什么时候用 |
|---|---|---|---|
| 51 | `ip addr` ★ | 看 IP、网卡状态 | 老命令 `ifconfig` 已废弃，答 `ip` 加分 |
| 52 | `ip route` | 看网关/路由 | 能 ping 通 IP 但域名不行 → 可能 DNS；都不同 → 看网关 |
| 53 | `ping -c 4 host` | 连通性 | 先 ping 网关，再 ping 外网，分层定位 |
| 54 | `ss -tlnp` ★★★ | 看监听端口和对应进程 | 查端口占用/服务有没有监听，`l`=listen `t`=tcp `n`=数字 `p`=进程 |
| 55 | `ss -tan state established \| wc -l` | 当前连接数 | 判断是不是连接打满 |
| 56 | `ss -s` | 连接状态汇总 | 一眼看 timewait/established 数量 |
| 57 | `curl -I url` ★ | 只看响应头 | 测 Web 是否正常，不下载正文 |
| 58 | `curl -o /dev/null -w "%{http_code}" url` | 只输出状态码 | 脚本里判断 200/502 |
| 59 | `nc -zv host 3306` ★★ | 测端口通不通 | **比 telnet 好用**，客户说「连不上数据库」先测这个 |
| 60 | `nslookup domain` / `dig` | 域名解析 | 解析对不对、解析到哪个 IP |

> **必答追问**：`ss -tlnp` 里没有你要的端口，说明什么？
> 三种可能：① 服务根本没起（先看 `systemctl status` 和日志）；② 起了但**只监听 127.0.0.1**，外部连不上（改 `bind 0.0.0.0`）；③ 端口被别的进程占了，服务启动失败。

## 附二：技术支持岗最常被问的 8 个「非命令」问题

| 问题 | 答题要点（30 秒版） |
|---|---|
| 用户说「网站打不开了」，你怎么问？ | 先确认范围：**一个人还是所有人**（本地网络问题 vs 服务端）→ 换浏览器/清缓存试 → 拿到 URL 和报错截图 → 服务端 `curl -I` 看状态码 → 502 查 upstream、502/504 查后端、403 查权限、DNS 查解析 |

| 怎么把日志发给开发 | `tail -n 500` 或按时间窗截取 → `grep` 过滤关键行 → 打包 `tar` → `scp`/工单附件。**别发整个 2G 日志** |
| 你改配置前会做什么 | 先 `cp x.conf x.conf.bak.$(date +%F)` 备份 → 改完 `nginx -t` 等语法检查 → `reload` 而不是 `restart` → 验证 → 记工单 |
| 遇到不会的怎么办 | 先自己查（官方文档/man/日志），**限时 30 分钟**；超时就带着「已排查什么、现象是什么、怀疑方向」去问，不要空手问 |

## 附三：10 个可能追问的原理（能答一句就够，别硬撑）

1. **软链接和硬链接**：软链是快捷方式（可跨分区、可链目录、源删了失效）；硬链是同一 inode 的另一个名字（不能跨分区、源删了还在）。
2. **inode 是什么**：文件元信息（权限、属主、大小、数据块位置），**文件名不在 inode 里**。所以 inode 满了一样写不进文件。
3. **`df` 和 `du` 为什么不一样**：`df` 问文件系统，`du` 遍历文件，差在已删除未释放的文件。
4. **load average 怎么算高**：和**核数**比，4 核 load 4.0 就是满载；超过核数持续高说明有排队。
5. **僵尸进程**：进程已退出但父进程没回收（`Z` 状态），杀不死，要处理父进程。
6. **`kill -9` 和 `-15`**：15 是请它退出（能收尾），9 是内核直接干掉（无法收尾）。
7. **端口被占用怎么处理**：`ss -tlnp` 找 PID → 判断能不能停 → 不能停就改端口。
8. **TIME_WAIT 是什么**：主动关闭的一方等 2MSL（60 秒），保证最后的 ACK 能重发、旧包消散。不是 bug。
9. **`/bin` 和 `/usr/bin`**：现代系统（CentOS 7+）已合并，`/bin` 是指向 `usr/bin` 的软链接。
10. **`chmod 777` 为什么危险**：所有人可读写执行，目录 777 谁都能删文件，等于关掉一层防护。
